## 三、数据库部署

### 3.1 安装 PostgreSQL 14

```bash
# Ubuntu/Debian
sudo sh -c 'echo "deb https://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list'
wget --quiet -O - https://www.postgresql.org/media/keys/ACCC4CF8.asc | sudo apt-key add -
sudo apt update
sudo apt install -y postgresql-14

# CentOS/RHEL
sudo yum install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-7-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo yum install -y postgresql14-server
sudo /usr/pgsql-14/bin/postgresql-14-setup initdb
sudo systemctl enable --now postgresql-14
```

### 3.2 创建数据库和用户

```bash
sudo -u postgres psql

-- 创建数据库用户（禁止使用postgres超级用户连接业务库）
CREATE USER splitter_app WITH PASSWORD 'YourStrongPassword2024!';

-- 创建数据库
CREATE DATABASE splitter_db OWNER splitter_app ENCODING 'UTF8' LC_COLLATE 'zh_CN.UTF-8' LC_CTYPE 'zh_CN.UTF-8' TEMPLATE template0;

-- 授权
GRANT ALL PRIVILEGES ON DATABASE splitter_db TO splitter_app;

-- 退出
\q
```

### 3.3 配置 pg\_hba.conf

```bash
# 编辑配置
sudo vim /etc/postgresql/14/main/pg_hba.conf

# 添加（仅允许应用服务器IP访问）
host    splitter_db    splitter_app    127.0.0.1/32    md5
host    splitter_db    splitter_app    10.0.0.0/24     md5

# 重启
sudo systemctl restart postgresql
```

### 3.4 配置 postgresql.conf 性能调优

```ini
# /etc/postgresql/14/main/postgresql.conf
max_connections = 100
shared_buffers = 2GB              # 内存25%
effective_cache_size = 6GB        # 内存75%
work_mem = 64MB
maintenance_work_mem = 512MB
random_page_cost = 1.1            # SSD优化
effective_io_concurrency = 200    # SSD优化
log_min_duration_statement = 500  # 慢查询记录(>500ms)
```

### 3.5 初始化数据库表结构

```bash
# 使用Prisma迁移创建表结构
npx prisma migrate deploy --name init

# 或手动执行SQL脚本
psql -U splitter_app -d splitter_db -f scripts/init_schema.sql
```

### 3.6 部分唯一索引（关键）

```sql
-- sys_user_community 部分唯一索引
CREATE UNIQUE INDEX uk_community_active
ON sys_user_community (community_id)
WHERE status = 1 AND is_deleted = 0;
```

### 3.7 数据备份策略

```bash
# 每日全量备份（crontab）
0 2 * * * pg_dump -U splitter_app splitter_db | gzip > /backup/pg/splitter_$(date +\%Y\%m\%d).sql.gz

# WAL归档增量备份（PITR）
# postgresql.conf
archive_mode = on
archive_command = 'test ! -f /backup/wal/%f && cp %p /backup/wal/%f'

# 保留30天
find /backup/pg -name "splitter_*.sql.gz" -mtime +30 -delete
```

```bash
JWT_REFRESH_EXPIRES=7d
```

### 6.2 Nginx托管静态文件

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL证书
    ssl_certificate     /etc/nginx/ssl/splitter.crt;
    ssl_certificate_key /etc/nginx/ssl/splitter.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # PC前端静态文件
    location / {
        root /opt/splitter/pc-frontend/dist;
        index index.html;
        try_files $uri $uri/ /index.html;  # SPA路由回退
    }

    # API反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket支持（如有实时通知）
    location /ws/ {
        proxy_pass http://127.0.0.1:3000/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 文件上传大小限制
    client_max_body_size 10M;
}
```

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 8.1 docker-compose.yml

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:14-alpine
    container_name: splitter-pg
    restart: always
    environment:
      POSTGRES_DB: splitter_db

  redis:
    image: redis:7-alpine
    container_name: splitter-redis

      - ./nginx/nginx.conf:/etc/nginx/nginx.conf
      - ./nginx/ssl:/etc/nginx/ssl
      - ./pc-frontend/dist:/usr/share/nginx/html
    depends_on:
      - api

volumes:
  pg_data:
  redis_data:
```

## 九、系统初始化流程

### 9.1 初始化顺序

```
1. PostgreSQL建库建表 → 2. Redis启动 → 3. 后端启动+Seed初始化
→ 4. Nginx启动 → 5. PC前端访问验证 → 6. 小程序发布
```

### 9.2 Seed初始化内容

| 初始化项    | 说明                                                             |
| ------- | -------------------------------------------------------------- |
| 超级管理员账号 | 账号: `admin`，密码: 随机生成打印至日志，`role_type=1`，`real_name_verified=1` |
| 行政区划数据  | 国标GB/T 2260全国省/市/区县三级数据导入 `sys_region` 表                       |
| 启动检查    | 检测 `sys_user` 表是否存在超级管理员，不存在则阻塞启动                              |

### 9.3 初始化后操作

1. 超级管理员使用 `admin` + 随机密码登录PC端，首次登录强制修改密码
2. 创建区域管理员账号，分配管辖区域（省/市）
3. 区域管理员创建管理员账号，分配区县
4. 管理员创建社区、操作员账号
5. 管理员为操作员分配社区权限
6. 操作员登录小程序/PC端开始运维

## 十、安全配置

### 10.1 SSL证书

```bash
# Let's Encrypt免费证书
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com

# 自动续期
sudo crontab -e
0 3 * * * certbot renew --quiet --post-hook "systemctl reload nginx"
```

### 10.2 防火墙

```bash
# 仅开放必要端口
sudo ufw allow 22/tcp        # SSH
sudo ufw allow 80/tcp        # HTTP
sudo ufw allow 443/tcp       # HTTPS
sudo ufw enable

# PostgreSQL和Redis仅本地访问
# 不对外暴露5432和6379端口
```

### 10.3 敏感信息保护

| 敏感数据    | 保护措施                       |
| ------- | -------------------------- |
| 用户密码    | bcrypt加密存储，cost=12         |
| 身份证号    | AES-256加密存储，密钥在.env中       |
| JWT密钥   | .env文件，权限600               |
| 数据库密码   | .env文件，权限600               |
| Redis密码 | .env文件 + redis.conf        |
| .env文件  | 不提交git，权限 `chmod 600 .env` |

```bash
chmod 600 /opt/splitter/.env.production
```

### 10.4 接口安全

- 所有业务接口强制JWT鉴权

- 小程序接口强制HTTPS

- 登录接口限流：单IP每分钟10次

- 实名认证限流：单用户每日5次

- 连续登录失败5次锁定30分钟

- JWT黑名单（Redis），登出/禁用即时失效

## 十三、CI/CD 持续集成与持续部署

> 本项目代码托管在 GitHub（`git@github.xspace:xspace0/splitter.git`），CI/CD 使用 GitHub Actions 原生方案，同时保留 Drone CI 作为自建免费替代方案。

### 13.1 CI/CD 方案选择

| 方案                 | 目录                   | 费用                  | 适用场景                  |
| ------------------ | -------------------- | ------------------- | --------------------- |
| **GitHub Actions** | `.github/workflows/` | 公开仓库免费，私有仓库2000分钟/月 | **当前主用方案**，GitHub原生集成 |
| Drone CI           | `.drone.yml`         | 开源免费（需自建Drone服务）    | 自建CI/CD，完全免费          |
| Gitee Go           | `.gitee/workflows/`  | Gitee付费版免费额度，超出收费   | 如迁移回Gitee时可用          |

### 13.2 CI/CD 架构

```
  开发者 Push/PR        自动构建          自动部署
      │                  │                │
      ▼                  ▼                ▼
 ┌─────────┐      ┌──────────┐     ┌──────────┐
 │ Git仓库  │ ──→ │ CI流水线  │ ──→ │ 生产服务器│
 │ (GitHub) │      │ lint+test│     │ Docker   │
 └─────────┘      │ build    │     │ 部署+检查 │
      │            │ docker   │     └──────────┘
      │            └──────────┘
      │                  │
      │            ┌──────────┐
      └──────────→ │ CD流水线  │
         tag触发    │ deploy   │
                     └──────────┘
```

### 13.2 流水线说明

| 流水线     | 触发条件                 | 执行内容                                      | 文件                             |
| ------- | -------------------- | ----------------------------------------- | ------------------------------ |
| CI 代码检查 | PR、Push到main/develop | ESLint + Prettier + TypeScript类型检查 + 单元测试 | `.github/workflows/ci.yml`     |
| CD 构建部署 | Push到main、打Tag、手动触发  | 后端Docker构建推送 + 前端构建 + SSH部署 + 健康检查        | `.github/workflows/deploy.yml` |

### 13.6 Dockerfile（多阶段构建）

## 十四、测试环境部署（单服务器双环境方案）

> 适用场景：只有一台服务器，需要同时承载测试环境和生产环境。
> 设计原则：**资源隔离、数据隔离、网络隔离、密钥隔离**，测试环境低配运行，不影响生产。

### 14.1 整体架构

```
                    ┌──────────────┐
                    │   Nginx      │
                    │  (443/80)    │
                    └──────┬───────┘
                           │
              ┌────────────┴────────────┐
              │                         │
     ┌────────▼────────┐       ┌────────▼────────┐
     │  生产环境         │       │  测试环境         │
     │  your-domain.com │       │ test.your-...   │
     │  (主域名)        │       │  (子域名)        │
     └────────┬─────────┘       └────────┬────────┘
              │                          │
    ┌─────────▼─────────┐      ┌─────────▼─────────┐
    │ splitter-api      │      │ splitter-test-api │
    │ :3000             │      │ :13000            │
    │ splitter-pg       │      │ splitter-test-pg  │
    │ :5432             │      │ :15432            │
    │ splitter-redis    │      │ splitter-test-redis│
    │ :6379             │      │ :16379            │
    └───────────────────┘      └───────────────────┘
         完整配置/高资源              精简配置/资源限制
```

**隔离要点**：

| 隔离项 | 生产环境 | 测试环境 |
|--------|----------|----------|
| 容器名前缀 | `splitter-*` | `splitter-test-*` |
| 数据卷 | `pg_data` / `redis_data` | `pg_test_data` / `redis_test_data` |
| 数据库 | `splitter_db` / 用户 `splitter_app` | `splitter_test_db` / 用户 `splitter_test` |
| 主机端口 | 5432 / 6379 / 3000 | 15432 / 16379 / 13000 |
| 访问域名 | `your-domain.com` | `test.your-domain.com` |
| JWT密钥 | 生产密钥 | 独立测试密钥 |
| 加密密钥 | 生产密钥 | 独立测试密钥 |
| CPU限制 | 无（默认全可用） | 总计 ≤ 1.7 核 |
| 内存限制 | 无（默认全可用） | 总计 ≤ 1.75GB |
| 微信AppID | 正式小程序 | 测试号（推荐） |

### 14.2 资源限制配置（关键）

测试环境所有服务都配置了 Docker 资源限制，防止测试环境异常（如死循环、压测）拖垮生产：

| 服务 | CPU 限制 | 内存限制 | 说明 |
|------|----------|----------|------|
| PostgreSQL | 0.5 核 | 512MB | 测试环境不需要高性能 |
| Redis | 0.2 核 | 256MB | 缓存数据量小 |
| API | 1.0 核 | 1GB | 单实例足够 |
| **合计** | **1.7 核** | **1.75GB** | 4核8G机器完全够用 |

配置位置：`docker-compose.test.yml` 中每个服务的 `deploy.resources.limits`。

### 14.3 Nginx 配置（双环境共用）

生产和测试共用同一个 Nginx 容器，通过 `server_name` 区分：

- 生产：`server_name your-domain.com` → 反代到 `api:3000`（内部网络）
- 测试：`server_name test.your-domain.com` → 反代到 `host.docker.internal:13000`（宿主机端口）

**测试环境访问保护**：默认开启 Basic Auth，防止外部随意访问测试环境。

```bash
# 生成密码文件（在服务器 nginx/ 目录下执行）
htpasswd -c nginx/.htpasswd tester
# 输入密码后，重启 Nginx 生效
```

如不需要 Basic Auth，注释掉 nginx.conf 中测试环境 server 块里的 `auth_basic` 两行即可。

### 14.4 测试环境部署步骤

#### 第一步：准备环境变量

```bash
cd /opt/splitter-test
cp server/.env.test.example .env.test
vim .env.test
# 填写数据库密码、Redis密码、JWT密钥等
# ⚠️  务必确保密钥与生产环境不同！
```

#### 第二步：启动测试环境

```bash
cd /opt/splitter-test
docker compose -f docker-compose.test.yml up -d

# 查看状态
docker compose -f docker-compose.test.yml ps

# 查看日志
docker logs splitter-test-api --tail 50
```

#### 第三步：初始化测试数据

```bash
# 执行数据库迁移（首次部署）
docker compose -f docker-compose.test.yml run --rm api npx prisma migrate deploy

# 执行 Seed 初始化（创建超级管理员、行政区划）
docker compose -f docker-compose.test.yml run --rm api npm run seed
```

#### 第四步：配置 Nginx（生产环境侧）

测试环境的 Nginx 配置在生产环境的 nginx 容器中：

```bash
# 1. 修改 nginx/nginx.conf 中的域名
#    将 test.your-domain.com 改为你的测试域名

# 2. 生成 htpasswd 文件（如需要 Basic Auth）
htpasswd -c nginx/.htpasswd tester

# 3. 准备测试环境前端产物
mkdir -p pc-frontend-dist-test
# 将测试环境前端构建产物放入此目录

# 4. 重启生产环境的 Nginx（只重启 Nginx，不影响 API 和数据库）
cd /opt/splitter
docker compose -f docker-compose.prod.yml restart nginx
```

#### 第五步：验证

```bash
# API 健康检查
curl http://127.0.0.1:13000/health

# 测试环境访问
# 浏览器打开 https://test.your-domain.com
# 输入 Basic Auth 用户名密码（如果开启了的话）
```

### 14.5 测试环境 CI/CD 自动部署

**触发条件**：push 到 `develop` 分支 → 自动部署到测试环境

**流水线文件**：`.github/workflows/deploy-test.yml`

**流水线步骤**：
1. 后端 Docker 构建 → 推送镜像（tag: `test`）
2. PC 前端构建（使用测试环境 API 地址）
3. SCP 传输文件到服务器测试环境目录
4. SSH 执行 `deploy.sh test test`
5. 健康检查验证

**需要配置的 Secrets**（仓库 → Settings → Secrets）：

| Secret 名 | 说明 |
|-----------|------|
| `ALIYUN_REGISTRY` | 镜像仓库地址 |
| `ALIYUN_REGISTRY_USERNAME` | 镜像仓库用户名 |
| `ALIYUN_REGISTRY_PASSWORD` | 镜像仓库密码 |
| `TEST_DEPLOY_HOST` | 测试服务器 IP（和生产同一台） |
| `TEST_DEPLOY_USER` | SSH 用户名 |
| `TEST_DEPLOY_SSH_KEY` | SSH 私钥 |
| `TEST_DEPLOY_DOMAIN` | 测试环境域名（如 test.example.com） |

> 💡 也可以和生产共用同一套部署密钥，用不同的目录区分。

### 14.8 安全注意事项

1. **密钥隔离**：测试环境的 JWT 密钥、身份证加密密钥必须与生产不同
2. **数据库隔离**：不同库、不同用户、不同密码，测试数据库用户权限更低
3. **访问控制**：测试环境开启 Basic Auth 或 IP 白名单，不对外公开
4. **数据安全**：不要把生产数据直接导入测试库，如需同步请先脱敏
5. **资源限制**：不要随意调大测试环境的资源限制，避免影响生产
