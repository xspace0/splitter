# 分光器资源管理系统\_权限模块需求.md（最终定稿V8-7）

> 角色编码：1-超级管理员、2-区域管理员、3-管理员、4-操作员、5-查看者。
> 本文档与数据库设计文档 V8-7 完全对齐。

## 1 概述

本文档定义分光器资源管理系统全部角色、功能权限、数据权限、接口鉴权规则、操作审计日志、页面访问控制。

### 1.1 全局前置约束

1. 所有业务接口必须携带JWT access\_token；账号`status=0`、`is_deleted=1`直接拦截，返回401/403。
2. 实名认证强约束：`real_name_verified=0`未实名认证账号，仅允许访问登录、个人中心实名认证相关接口。**分光器列表页面、地图页面、社区管理页面、用户管理页面，无论任何角色访问，必须校验`real_name_verified=1`；未认证直接拦截，跳转个人中心提示完成实名认证。**
3. 所有写操作均做服务端二次校验，不能仅依赖前端按钮显隐控制权限。
4. 操作员数据权限依赖`sys_user_community.user_id=当前用户 AND status=1 AND is_deleted=0`有效分配记录；不再依靠`region_id`读取本区县全部数据。
5. 权限变更不会主动销毁现有token，**用户下一次接口请求才会按照新权限规则校验；前端页面旧缓存由前端自行处理**。
6. 角色提升规则：若要将用户提升至操作员及以上角色，目标账号必须完成实名认证；因此系统不存在未实名认证的操作员、管理员、区域管理员、超级管理员账号。
7. 业务状态强制规则：

   - 社区`status=0`停用：**全部角色（含超级管理员），在社区恢复status=1正常启用之前，社区本身以及下属分光器只允许读取，禁止全部写操作**；恢复启用后方可进行新增、编辑、删除等写操作。

   - `is_deleted=1`逻辑删除（社区、分光器）：任何角色禁止写操作；普通角色读也拿不到；超级管理员仅可读取用于审计恢复。
8. 社区停用-删除业务规则（对齐数据库设计 V8-7）：

   - 社区允许带分光器执行停用（status置0），停用时自动记录`disable_time`；停用后社区及下属分光器全部只读，禁止一切写操作。

   - 社区停用满30天（`disable_time`距当前时间≥30天）后方可执行逻辑删除；不满足条件返回错误码3011。

   - 执行社区逻辑删除时，应用层自动将该社区下所有未删除分光器批量逻辑删除（`is_deleted=1`），无数据库物理级联；批量变更写入操作日志，注明"因所属社区删除，批量逻辑删除"。

   - 社区从停用恢复正常状态时，清空`disable_time`，30天删除计时重置，分光器恢复正常读写权限。
9. 行政区划`sys_region`为静态国标字典表，业务系统不提供增删改接口，全部由后台导入脚本维护，不走业务操作日志。
10. 账号`account`、微信`wx_openid`全局永久唯一（含逻辑删除数据），禁止复用；社区名称`community_name`、分光器名称`splitter_name`在未删除状态下唯一；唯一约束冲突返回错误码1003。

### 3.1 特殊数据权限业务规则

1. **操作员查询过滤**

   - 查询社区：仅返回`sys_user_community.user_id=当前用户 AND sys_user_community.status=1 AND sys_user_community.is_deleted=0`的社区，过滤本区县其余未分配社区；同时过滤`community.is_deleted=1`逻辑删除社区。

   - 查询分光器：关联`sys_user_community`过滤（`status=1 AND is_deleted=0`），只返回分配社区下属分光器；不再通过`region_id`读取本区县全部分光器；过滤分光器`is_deleted=1`。

   - 地图渲染：只绘制分配社区范围内分光器点位；过滤逻辑删除社区；`status=0`停用社区数据正常返回，前端视觉置灰标记停用。
2. **社区状态强制规则**

   - `is_deleted=1`逻辑删除社区：区域管理员、管理员、操作员、查看者接口直接过滤不返回；超级管理员可查询；**任何角色禁止写**。

   - `status=0`停用社区：全部角色可读；**全部角色（含超级管理员）禁止新增、编辑、删除、故障录入等全部写操作；必须恢复status=1才可执行写操作**。
3. **社区停用-删除业务规则（对齐数据库设计 V8-7）**

   - 社区允许带分光器执行停用，停用时自动记录`disable_time`，社区及下属分光器全部只读。

   - 社区停用满30天（`disable_time`距当前时间≥30天）后方可执行逻辑删除；不满足返回错误码3011。

   - 执行社区逻辑删除时，应用层自动将该社区下所有未删除分光器批量逻辑删除（`is_deleted=1`），无数据库物理级联。

   - 社区从停用恢复正常状态时，清空`disable_time`，30天删除计时重置，分光器恢复正常读写权限。

   - 社区逻辑删除与分光器逻辑删除的批量变更均需写入操作日志，`operation_content`注明"因所属社区删除，批量逻辑删除"。
4. **sys\_user\_community 用户-社区关联表**

   - 部分唯一索引`uk_community_active (community_id) WHERE status=1 AND is_deleted=0`，保证同一社区有效状态下仅分配一个操作员。

   - 权限移除：`status`置0逻辑失效，不物理删除，保留审计记录；权限置0后操作员查询不再返回该社区数据。

   - 记录逻辑删除：`is_deleted`置1，与`status=0`语义不同；`is_deleted=1`表示记录本身被逻辑删除。
5. **分光器拓扑约束**

   - 修改`parent_id`父设备ID，必须校验父子分光器归属同一社区；父分光器存在未删除子分光器，禁止逻辑删除父分光器。

   - 分光器存在未删除子节点时禁止修改`splitter_level`设备级别，返回错误码3012；仅无子节点设备允许修改，修改后同步校验新层级与父子拓扑完全匹配。

   - 分光器status由故障切换为正常/停用/建设中状态时，必须清空`fault_type`字段；禁止非故障状态携带故障类型。
6. **region\_id隔离规则**
   区域管理员、管理员、查看者依靠`region_id`实现数据隔离；操作员完全依靠`sys_user_community`（`status=1 AND is_deleted=0`）分配记录过滤。
7. **查看者社区权限补充**

   - 查看者的本区县全部社区（只读）权限**仅开放给地图社区下拉选项接口**；返回条件：`community.is_deleted=0`；status=0停用社区正常返回，前端置灰标记；

   - 禁止访问社区管理页面、社区管理列表接口，不能读取社区完整管理台账字段；

   - 操作员地图下拉只展示本人被分配社区（`sys_user_community.status=1 AND is_deleted=0`）。

| 逻辑删除校验     | 业务统一is\_deleted逻辑删除；分光器父节点删除前置校验无子分光器；权限关联表status=0逻辑失效或is\_deleted=1逻辑删除；全部逻辑删除行为落操作日志；   普通角色查询接口过滤`is_deleted=1`业务记录，超级管理员不过滤，但全部角色禁止对is\_deleted=1数据做写操作                                                                                  |
| 唯一约束校验     | account、wx\_openid全局永久唯一（含逻辑删除数据）；community\_name、splitter\_name未删除状态下唯一；冲突返回错误码1003                                                                                                                                                          |
| 查看者接口特殊校验  | 1.拒绝访问社区管理页面、社区管理列表接口；   2.放行地图社区下拉选项接口，返回本区县`is_deleted=0`全部社区ID、名称用于筛选，status=0停用社区正常返回；   3.允许读取本区县全部分光器（过滤is\_deleted=1）；全部写接口返回403；不开放导出接口                                                                                               |
| 限流规则       | 账号登录接口限流；实名认证提交接口单用户每日上限5次；连续登录失败锁定账号                                                                                                                                                                                                         |

## 6 操作审计日志（sys\_operation\_log）

sys\_operation\_log为只追加表，**不可修改、不可删除，日志至少保存 5 年**。
约定：逻辑删除操作（`is_deleted=1` / 关联表`status=0`）操作类型标记为"删除"；`operation_content`以JSON存储变更前关键字段，用于审计回溯。社区删除批量级联分光器时，`operation_content`写明"因所属社区删除，批量逻辑删除"。

操作类型枚举（中文）：登录 / 登出 / 新增 / 修改 / 删除 / 权限分配 / 角色变更 / 故障上报 / 故障恢复。
操作对象类型枚举（中文）：用户 / 社区 / 分光器 / 权限。

| 序号 | 操作行为                                       |
| -- | ------------------------------------------ |
| 1  | 用户登录、登出                                    |
| 2  | 账号新增、启用、禁用、逻辑删除用户账号、重置密码                   |
| 3  | 用户角色升降级切换                                  |
| 4  | 操作员社区权限分配、权限移除（sys\_user\_community记录逻辑失效） |
| 5  | 社区新增、编辑、停用、恢复启用、社区逻辑删除（含批量级联分光器逻辑删除）       |
| 6  | 分光器新增、编辑、故障上报、故障恢复、分光器逻辑删除、修改设备级别          |
| 7  | 用户实名认证通过事件                                 |

> 注：行政区划`sys_region`由后台导入脚本维护，属于运维操作，不走业务操作日志。

## 8 补充业务说明

1. 删除全部为逻辑删除：业务表使用`is_deleted`，权限关联表`sys_user_community`使用`status`（权限移除）和`is_deleted`（逻辑删除），保留原始数据用于审计，不物理删除记录。
2. 父子分光器拓扑强校验，防止跨社区挂载、父节点带子节点被删除的脏数据；**无数据库外键，全部在后端代码实现校验**。
3. 小程序与PC端同一套用户体系；小程序用户升级管理员时补充`account`账号与密码，实现PC与小程序身份互通。
4. **社区停用-删除完整流程（对齐数据库设计 V8-7）**

   - 社区允许带分光器执行停用（status置0），停用时自动记录`disable_time`；停用后社区及下属分光器全部只读，禁止一切写操作（新增、修改、故障上报、删除、修改归属社区均拦截）。

   - 社区停用满30天（`disable_time`距当前时间≥30天）后方可执行逻辑删除；不满足返回错误码3011。

   - 执行社区逻辑删除时，应用层自动将该社区下所有未删除分光器批量逻辑删除（`is_deleted=1`），无数据库物理级联。

   - 社区从停用恢复正常状态时，清空`disable_time`，30天删除计时重置，分光器恢复正常读写权限。

   - `is_deleted=1`逻辑删除社区：区域管理员、管理员、操作员、查看者接口直接过滤，拿不到数据；超级管理员可查询，用于审计、数据恢复；**任何角色禁止写**。
5. 操作员权限被移除（sys\_user\_community.status置0或is\_deleted置1）：接口不再返回该社区及下属分光器；权限变更不会销毁当前token，**下一次接口请求按新权限规则校验，前端旧页面缓存由前端处理**。
6. 边界提示：社区`status=0`停用时，下属分光器即使当前处于故障状态，也不允许执行故障恢复操作，需先恢复社区为正常启用状态。
7. 操作审计日志至少保存5年，到期后归档至冷存储介质。
8. 行政区划`sys_region`为静态国标字典，业务系统不提供增删改接口，全部由后台导入脚本维护，不走业务操作日志。
9. 账号`account`、微信`wx_openid`全局永久唯一（含逻辑删除数据），禁止复用；社区名称`community_name`、分光器名称`splitter_name`未删除状态下唯一；冲突返回错误码1003。
10. 分光器设备名称`splitter_name`（varchar(128)，非空）用于台账、树形展示、检索；未删除状态下唯一。
