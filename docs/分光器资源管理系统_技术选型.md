# 分光器资源管理系统-技术选型（Node.js + NestJS + TypeScript）

> 背景：PC管理后台 + 微信小程序；行级数据权限、分光器树形拓扑、GIS地图点位、Excel导入导出、AOP审计日志、JWT鉴权、逻辑删除；数据库 PostgreSQL；全量使用 TypeScript 强类型约束，类型定义和数据库表结构一一对应。

## 三、TypeScript重点设计 & 核心业务实现要点

### 3.1 类型来源

1. **数据库实体类型：由Prisma自动生成`@prisma/client`，TypeScript直接复用DB表字段类型，保证前后端接口实体和数据库字段不会错位。**
2. 手动定义：DTO入参、Response返回体、业务枚举、业务常量全部TS枚举/interface/type。

> 示例：角色枚举（TS）

```typescript
export enum RoleType {
  SUPER_ADMIN = 1,
  REGION_ADMIN = 2,
  ADMIN = 3,
  OPERATOR = 4,
  VIEWER = 5,
}
```

> 示例：业务状态枚举

```typescript
export enum CommunityStatus {
  NORMAL = 1,
  DISABLED = 0,
}
export enum DeleteFlag {
  NORMAL = 0,
  DELETED = 1,
}
```

> 示例：操作日志枚举（存储值为中文）

```typescript
export enum OperationType {
  LOGIN = '登录',
  LOGOUT = '登出',
  CREATE = '新增',
  UPDATE = '修改',
  DELETE = '删除',
  ASSIGN = '权限分配',
  ROLE_CHANGE = '角色变更',
  FAULT_REPORT = '故障上报',
  FAULT_RESOLVE = '故障恢复',
}

export enum TargetType {
  USER = '用户',
  COMMUNITY = '社区',
  SPLITTER = '分光器',
  PERMISSION = '权限',
}
```

### 3.2 NestJS-Guard守卫（TS实现鉴权、实名认证）

- 从JWT解析`user_id`、`role_type`、`jti`；

- 根据`user_id`查询数据库获取完整用户Prisma实体，**不使用JWT内的业务数据**；

- TS校验账号：`status ===1 && is_deleted ===0`；校验Redis黑名单jti；

- TS强制校验实名认证：`real_name_verified ===1`，不满足直接抛出403 Forbidden；

- 将完整用户实体挂载到`req.user`，后续Service使用TS类型约束Request。

### 3.3 行级数据权限（Service层 TypeScript + Prisma）

1. **操作员查询社区、分光器 TS-Prisma查询条件**

```typescript
const whereCondition = {
  sys_user_community: {
    user_id: currentUserId,
    status: 1,
    is_deleted: DeleteFlag.NORMAL,
  },
  community: {
    is_deleted: DeleteFlag.NORMAL,
  },
};
```

1. 超级管理员查询：**不拼接`is_deleted`过滤条件，可以查询逻辑删除记录用于审计恢复**；
2. **分光器写操作，TS四层业务校验（所有角色包含超级管理员）**

   - ①分光器归属社区属于本人`sys_user_community.status=1 AND is_deleted=0`有效分配集合

   - ②父子分光器归属同一个`community_id`

   - ③归属社区`community.status === CommunityStatus.NORMAL`（社区必须正常启用）

   - ④目标业务记录`is_deleted === DeleteFlag.NORMAL`（逻辑删除记录全员禁止写）

> 社区`status=0`停用：TS代码拦截全部写接口，全员只可读，必须恢复为`1`才允许写。

### 3.4 sys\_operation\_log审计日志（TS AOP拦截器）

1. 自定义装饰器 `@OperationLog({ operationType: OperationType.CREATE, targetType: TargetType.COMMUNITY })` TS强类型参数；
2. Interceptor拦截器执行：执行接口前查询旧Prisma实体，序列化为JSON；接口成功后组装日志对象；
3. **TS代码限制该表只执行prisma.create，禁止prisma.update / prisma.delete，不对外暴露修改删除接口；**
4. IP、User-Agent从Request对象获取，写入日志；日志保存至少5年，到期脚本迁移冷存储。

### 3.5 分光器树形拓扑（PostgreSQL CTE + TS业务校验）

- 使用Prisma执行原始SQL `WITH RECURSIVE`递归CTE拿到树形原始数据；

- **拓扑校验全部TypeScript业务代码实现：设备级别校验、父子同社区、删除前校验子节点存在、检测parent\_id循环引用；无数据库物理外键。**

### 3.6 JWT-黑名单 TS逻辑

1. JWT payload存放`jti`唯一token编号；
2. 用户登出/账号禁用：将jti写入Redis；key过期时间与JWT有效期完全对齐；
3. Guard鉴权时TS校验Redis黑名单，命中返回401；
4. **权限变更不销毁JWT，TS代码约定：下一次接口请求实时查询DB权限，前端自行处理页面缓存。**

### 3.7 Excel导入 exceljs TS

流式读取；每一行解析后转TS DTO；先做DTO类型校验；再完整执行全套业务校验（权限、拓扑、社区状态、逻辑删除），**绝不信任Excel原始输入。**

## 四、不选用组件 & 避坑清单

1. ❌不使用TypeORM：Prisma自动生成TypeScript数据库实体，对PostgreSQL条件唯一索引、JSON、CTE递归支持更好。
2. ❌不建立数据库物理外键：所有关联、父子、引用完整性全部TypeScript Service层校验；仅保留`uk_community_active`条件唯一索引（`WHERE status=1 AND is_deleted=0`）。
3. ❌不引入PostGIS：经纬度decimal存储；GIS渲染、空间计算全部前端，后端不做空间运算。
4. ❌不使用通用RBAC权限表：框架RBAC无法满足本系统**按社区分配的行级数据权限**；权限完全依赖业务表`sys_user`、`sys_user_community`，TS定义对应实体。
5. ❌业务数据禁止Redis缓存，防止权限变更脏缓存；仅缓存黑名单、限流、字典。
6. ❌不依靠前端做权限控制，**所有功能、数据、写操作全部后端TS代码强制校验；前端只做交互体验。**

## 五、安全&部署要点

1. `id_card_no`身份证：node crypto模块TS加密存入数据库，禁止明文。
2. 用户密码：bcryptjs cost=12加密，TS类型约束，禁止明文存储。
3. Prisma参数化查询，TS天然防护SQL注入。
4. sys\_operation\_log仅追加；保存5年，到期迁移冷存储。
5. 小程序接口强制HTTPS。
6. Redis黑名单过期时间和JWT过期时间对齐。
