### 3.2 模块分层说明

每个业务模块遵循标准 NestJS 分层：

| 层级 | 文件 | 职责 |
|------|------|------|
| Controller | `*.controller.ts` | 处理 HTTP 请求路由、参数校验、调用 Service |
| Service | `*.service.ts` | 核心业务逻辑、数据权限校验、调用 Prisma |
| DTO | `dto/*.dto.ts` | 请求参数类型定义与校验规则（class-validator） |
| Entity | `entities/*.entity.ts` | 响应实体类型定义（Swagger 注解） |
| Module | `*.module.ts` | 模块注册、依赖注入 |

### 3.3 关键设计原则

1. **按领域划分模块**：社区、分光器、用户、权限各为独立模块，职责清晰
2. **Service 层做权限校验**：所有写操作在 Service 层进行二次权限校验，不依赖前端传参
3. **Prisma 统一封装**：通过 `PrismaService` 扩展逻辑删除等通用能力
4. **AOP 操作日志**：通过 `@OperationLog()` 装饰器 + Interceptor 实现审计日志
5. **Guard 全局鉴权**：JWT 认证、角色校验、实名认证统一在 Guard 层处理

### 4.2 环境变量

| 位置 | 用途 |
|------|------|

`docker-compose.prod.yml` / `docker-compose.test.yml` 需要增加：
- `backend` 服务（Node.js + NestJS，PM2 进程守护）
- `postgres` 服务（数据库）
- `redis` 服务（缓存）

### 4.4 脚本

| 脚本位置 | 用途 |
|----------|------|
| 根目录 `scripts/` | 全项目部署、回滚、CI 脚本 |
| `server/package.json scripts` | 后端开发、构建、测试、数据库迁移命令 |

## 五、后端开发常用命令

```bash
cd server

# 安装依赖
npm install

# 开发模式（热重载）
npm run start:dev

# 构建生产版本
npm run build

# Prisma 数据库迁移
npx prisma migrate dev --name init

# Prisma 生成 Client
npx prisma generate

# 执行初始化数据
npx prisma db seed

# 运行测试
npm run test
npm run test:e2e
```

## 六、演进路径

如果未来项目规模扩大，可平滑升级到 Monorepo 结构：

```
splitter/
├── packages/
│   ├── client/            # 前端（从根目录迁移）
│   ├── server/            # 后端（从 server/ 迁移）
│   └── shared/            # 共享类型、枚举、工具
├── package.json           # 根 package.json（pnpm workspace）
└── pnpm-workspace.yaml
```

当前阶段使用轻量子目录方案即可满足需求，无需过度工程化。
