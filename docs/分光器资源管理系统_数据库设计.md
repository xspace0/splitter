# 分光器资源管理系统\_数据库设计文档

## 1 概述

### 1.1 设计原则

1\. 不使用数据库物理外键，引用、拓扑、业务完整性全部由应用代码校验；保留关联字段保证可读性。

2\. 业务表统一采用逻辑删除；静态字典表`sys_region`无审计、无逻辑删除字段，由后台脚本导入维护。

3\. 操作日志为只追加表，不可修改、不可删除，日志数据至少保留5年。

4\. 全部业务数据表主键统一字段名称为`id`。

### 1.2 通用字段说明

说明：`sys_region`行政区划表不使用本节通用字段；`sys_operation_log`操作日志表存在局部例外。

| 字段名          | 数据类型      | 约束               | 说明                              |
| ------------ | --------- | ---------------- | ------------------------------- |
| id           | bigint    | 主键、自增、非空         | 业务表统一主键                         |
| is\_deleted  | smallint  | 默认值0、非空          | 逻辑删除：0‑正常，1‑已删除；业务禁止物理删除        |
| create\_time | timestamp | 默认当前时间、非空        | 创建时间，程序不可手动赋值                   |
| update\_time | timestamp | 默认当前时间、更新自动刷新、非空 | 更新时间，数据库自动刷新                    |
| creator\_id  | bigint    | 可为空              | 创建人用户ID；系统初始化数据可为空；代码校验用户存在且未删除 |

### 1.3 通用字段例外规则

1\. **sys\_operation\_log（操作日志）**：仅保留`id`、`create_time`；无`is_deleted`、`update_time`、`creator_id`；使用`user_id`记录操作人。

2\. **sys\_region（行政区划）**：静态国标字典，无`is_deleted`、`create_time`、`update_time`、`creator_id`；前端仅提供查询能力，增删改全部由后台导入脚本执行；后台导入属于运维操作，业务系统不记录操作日志。

## 2 全局枚举定义

### 2.1 社区状态 status

可选枚举值：`1:正常`、`0:停用`；正常状态可读可写，支持执行停用操作；停用状态全部角色仅可读，下属分光器全部只读，禁止任何写操作。

### 2.2 分光器状态 status

可选枚举值：`1:正常`、`2:故障`、`3:停用`、`4:建设中`；故障状态下fault\_type字段必填；非故障状态（正常、停用、建设中）禁止保留fault\_type故障数据；建设中状态允许写操作；是否有子设备取决于设备级别而非状态；建设中切换为正常无需审批；社区停用时建设中设备同样变只读。

### 2.3 分光器设备级别 splitter\_level

可选枚举值：`1:光交`、`2:一级分光器`、`3:二级分光器`、`4:光缆成端`；光交为根节点，parent\_id可为空；一级分光器父节点必须为光交；二级分光器父节点必须为一级分光器；光缆成端父节点必须为二级分光器。

### 2.4 分光器分路比 split\_ratio

可选枚举值：`1:8`、`1:16`、`1:32`、`1:64`；级别1/2/3设备非空，级别4光缆成端可为空。

### 2.5 分光器故障类型 fault\_type（status=2时必填）

可选枚举值：`1:无光`、`2:光大`、`3:箱体损坏`、`4:拆移改`。

### 2.6 用户实名认证状态 real\_name\_verified

可选枚举值：`0:未认证`、`1:已认证`；未认证拦截分光器、社区、地图、用户管理核心业务接口；已认证正常放行业务权限。

### 2.7 用户角色类型 role\_type

可选枚举值：`1:超级管理员`、`2:区域管理员`、`3:管理员`、`4:操作员`、`5:查看者`；超级管理员可查询逻辑删除数据，不可对停用社区、逻辑删除记录执行写操作；区域管理员绑定省、市数据维度；管理员绑定区县数据维度；操作员负责设备运维、故障上报业务；查看者仅查询只读，无写权限。

### 2.8 行政区划层级 region\_level

可选枚举值：`1:省`、`2:市`、`3:区县`。

## 3 数据表详细设计

### 3.1 sys\_user 系统用户表

用途：存储系统账号、实名信息、角色、所属区域等用户数据

索引说明：普通唯一索引`uk_account(account)`；账号全局不可重复，**无论是否逻辑删除均禁止账号复用**；小程序用户account允许为NULL，NULL不参与唯一性校验。

补充索引规则：`wx_openid` 遵循与account一致的约束规则，全局永久唯一，已逻辑删除的用户openid禁止复用，保障微信账号绑定唯一性。

| 字段名                    | 数据类型      | 约束               | 说明                          |
| ---------------------- | --------- | ---------------- | --------------------------- |
| id                     | bigint    | 主键、自增、非空         | 用户主键                        |
| username               | varchar   | 非空               | 实名姓名                        |
| account                | varchar   | 可为空、全局唯一         | PC登录账号；全表唯一不可复用；小程序用户可为空    |
| password\_hash         | varchar   | 可为空              | bcrypt加密（cost=12）；微信登录用户可为空 |
| wx\_openid             | varchar   | 可为空、全局唯一         | 小程序openid                   |
| wx\_unionid            | varchar   | 可为空              | 微信开放平台unionid               |
| wx\_avatar             | varchar   | 可为空              | 头像url                       |
| real\_name\_verified   | smallint  | 默认值0、非空          | 实名认证状态                      |
| real\_name\_auth\_time | timestamp | 可为空              | 认证通过时间                      |
| id\_card\_no           | varchar   | 可为空              | 身份证，加密存储                    |
| role\_type             | smallint  | 非空               | 用户角色                        |
| region\_id             | bigint    | 可为空              | 关联sys\_region.id；代码校验区域记录存在 |
| phone                  | varchar   | 可为空              | 手机号                         |
| status                 | smallint  | 默认值1、非空          | 账号：1启用 0禁用                  |
| last\_login\_time      | timestamp | 可为空              | 最后登录时间                      |
| is\_deleted            | smallint  | 默认值0、非空          | 逻辑删除                        |
| creator\_id            | bigint    | 可为空              | 创建人id                       |
| create\_time           | timestamp | 默认当前时间、非空        | 创建时间                        |
| update\_time           | timestamp | 默认当前时间、更新自动刷新、非空 | 更新时间                        |

### 3.2 community 社区表

用途：数据权限核心维度，分光器归属载体

索引说明：`uk_community_name(community_name)`，社区名称未删除状态下唯一

| 字段名             | 数据类型      | 约束               | 说明                                                 |
| --------------- | --------- | ---------------- | -------------------------------------------------- |
| id              | bigint    | 主键、自增、非空         | 社区主键                                               |
| community\_name | varchar   | 非空               | 社区名称                                               |
| region\_id      | bigint    | 非空               | 关联sys\_region.id；代码校验区域为区县层级                       |
| remark          | varchar   | 可为空              | 备注                                                 |
| status          | smallint  | 默认值1、非空          | 社区状态：1‑正常，0‑停用                                     |
| disable\_time   | timestamp | 可为空              | 社区停用时间；status改为0停用时赋值当前时间；恢复为正常状态置空；用于计算删除等待30天窗口期 |
| is\_deleted     | smallint  | 默认值0、非空          | 逻辑删除                                               |
| creator\_id     | bigint    | 非空               | 创建人id                                              |
| create\_time    | timestamp | 默认当前时间、非空        | 创建时间                                               |
| update\_time    | timestamp | 默认当前时间、更新自动刷新、非空 | 更新时间                                               |

**业务约束**

1\. 社区下存在未删除分光器，允许执行停用操作；停用后社区及下属分光器全部只读，禁止全部写操作（新增、修改、故障上报、删除、修改归属社区均拦截）；执行停用向绑定操作员、区县管理员、超级管理员发送系统通知。

2\. 应用层强校验：社区status=0（停用）时，disable\_time必须赋值当前时间；status恢复为1（正常）时，disable\_time必须置为NULL。

3\. 删除社区前置条件（全部满足才可删除，不满足返回错误码3011）：①社区status=0已停用；②disable\_time不为空，距离当前时间≥30天。

4\. 社区执行逻辑删除时，应用层代码自动将该社区下所有分光器执行逻辑删除`is_deleted=1`；数据库无物理级联；删除成功发送系统通知，通知提示社区及下属分光器已逻辑删除。

5\. 社区从停用恢复为正常状态，清空disable\_time，30天删除计时重置；分光器恢复正常读写权限。

### 3.3 optical\_splitter 分光器资源表

用途：核心业务表，存储光交、分光器、光缆成端，维护树形拓扑

索引说明：`uk_splitter_name(splitter_name)`，设备名称未删除状态下唯一

| 字段名               | 数据类型          | 约束                 | 说明                           |
| ----------------- | ------------- | ------------------ | ---------------------------- |
| id                | bigint        | 主键、自增、非空           | 设备主键                         |
| splitter\_name    | varchar(128)  | 非空                 | 设备名称，用于台账、树形展示、检索            |
| community\_id     | bigint        | 非空                 | 归属社区id；父子设备community\_id必须相等 |
| splitter\_level   | smallint      | 非空                 | 设备级别                         |
| parent\_id        | bigint        | 可为空                | 父设备id，自引用本表id；光交必须为空         |
| split\_ratio      | varchar       | 级别1‑3非空，级别4可为空     | 分路比；1‑3级必填，4级为空              |
| install\_location | varchar       | 可为空                | 安装位置文本描述                     |
| longitude         | decimal(10,7) | 可为空                | GCJ‑02火星坐标系经度，地图定位时填写        |
| latitude          | decimal(10,7) | 可为空                | GCJ‑02火星坐标系纬度，地图定位时填写        |
| status            | smallint      | 默认值1、非空            | 设备运行状态                       |
| fault\_type       | smallint      | status=2必填，其余状态可为空 | 故障类型，status=2故障状态必填，正常/停用/建设中状态可为空 |
| remark            | varchar       | 可为空                | 备注                           |
| operator\_id      | bigint        | 非空                 | 最后操作人用户id                    |
| is\_deleted       | smallint      | 默认值0、非空            | 逻辑删除；所属社区被逻辑删除时由应用层批量置为1     |
| creator\_id       | bigint        | 非空                 | 创建人id                        |
| create\_time      | timestamp     | 默认当前时间、非空          | 创建时间                         |
| update\_time      | timestamp     | 默认当前时间、更新自动刷新、非空   | 更新时间                         |

**业务补充约束**

1\. 应用层校验：分光器status由2故障切换为正常/停用/建设中状态时，必须清空fault\_type字段；禁止非故障状态携带故障类型。

2\. 应用层校验：分光器存在任意未删除子节点时，禁止修改自身splitter\_level字段，防止树形层级关系错乱；仅无子节点、无下级关联的设备允许修改设备级别，修改后同步校验新层级与父子拓扑完全匹配。

## 4 级联地址实现方案

依托静态字典`sys_region`实现省‑市‑区县三级级联选择：

1\. 前端新增/编辑社区：从sys\_region下拉选择区县，自动带出省市。

2\. 前端新增/编辑分光器：选择社区后，自动锁定该社区对应的region\_id，区县维度不可手动修改。

3\. 后端强校验：分光器归属区县必须与所属社区区县一致，不一致返回参数错误（4001）。

4\. sys\_region本身业务页面不可编辑，仅后台脚本导入更新，运维导入操作不写入业务操作日志。

## 5 应用层强制校验清单（替代数据库外键）

### 5.1 通用引用校验

新增、修改时，所有关联id（region\_id / creator\_id / operator\_id / parent\_id / user\_id / community\_id / target\_id）必须校验：

\- 业务表记录：存在且`is_deleted=0`，业务状态合法；

\- sys\_region：仅校验记录存在，该表无逻辑删除字段。

校验失败直接拒绝保存，返回参数错误。

### 5.2 分光器树形拓扑校验

1\. 光交 level=1 → parent\_id 必须为空

2\. 一级分光器 level=2 → parent\_id 必须是level=1，父子community\_id相同

3\. 二级分光器 level=3 → parent\_id 必须是level=2，父子community\_id相同

4\. 光缆成端 level=4 → parent\_id 必须是level=3，父子community\_id相同

5\. 删除分光器前：检查不存在未删除子设备；

6\. 禁止 parent\_id 形成循环引用。

### 5.3 数据权限与社区业务规则

1\. 超级管理员：查询不过滤`is_deleted=1`用于审计；但不能对停用社区、逻辑删除记录执行写。

2\. 区域管理员 / 管理员 / 操作员 / 查看者：查询自动过滤 `is_deleted=1`。

3\. 社区 status=0（停用）：所有角色只可读；社区、下属分光器全部写操作拦截。

4\. 社区删除：满足停用且停用满30天，应用层逻辑删除社区，同时批量逻辑删除下属分光器；批量变更需要写入操作日志，注明批量来源。

5\. 权限区分：

\- 3002：用户已有有效社区分配，但访问其它社区资源（越权）

\- 3007：操作员无任何有效社区分配，禁止写操作

两个错误码场景互斥。

### 5.4 日志约束

sys\_operation\_log 只做插入；不做引用完整性校验，可以记录已经被删除业务id，用于审计溯源。

sys\_region行政区划后台导入属于运维操作，不走业务操作日志。

社区删除批量级联分光器，每条分光器记录需要留存审计痕迹，日志`operation_content`写明“因所属社区删除，批量逻辑删除”。
