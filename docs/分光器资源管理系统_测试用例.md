# 分光器资源管理系统\_测试用例

## 一、前置环境与全局业务规则

1. 数据库不使用物理外键，全部约束由代码层实现；

2. 所有写操作**由后端全权校验权限，前端仅做视觉展示，不可信任前端权限标识**；

3. 操作日志 sys\_operation\_log 为只追加数据表，禁止修改、删除，日志数据保留5年；

4. 所有业务报错严格对齐《分光器资源管理系统\_业务错误码》，无自定义临时错误码；

5. 核心数据规则：

   - 社区停用 status=0：全员可读，**所有角色（含超级管理员）禁止一切写操作**；

   - 数据逻辑删除 is\_deleted=1：普通角色查询直接过滤，超级管理员仅可读审计，**全员禁止写操作**；

   - 地图下拉接口：返回本区县全部正常/停用社区（停用社区前端置灰），逻辑删除社区后端直接过滤不返回。

6. 权限互斥规则：

   - 3002：已有社区分配，越权访问其他社区/资源；

   - 3007：账号无任何社区分配，执行写操作，场景完全不重叠。

7. 社区停用-删除业务规则：

   - 社区允许带分光器执行停用，停用后社区及下属分光器全部只读；

   - 社区停用满30天（disable\_time距当前时间≥30天）后方可执行逻辑删除；

   - 执行社区逻辑删除时，自动批量逻辑删除下属分光器，写入操作日志；

   - 社区恢复正常状态时清空disable\_time，30天计时重置。

8. 行政区划 sys\_region 为静态国标字典，业务系统不提供增删改接口，由后台导入脚本维护，不走业务操作日志。

9. 唯一约束：account、wx\_openid全局永久唯一（含逻辑删除数据）；community\_name、splitter\_name未删除状态下唯一；冲突返回1003。
