### P0-2 登录响应结构前后端不一致，token 与用户缓存全是 undefined

| 项 | 内容 |
| --- | --- |
| **问题** | 后端返回 `{ token, user: { id, account, ... } }`（user 内嵌套），前端 `LoginView` 按扁平结构 `res.data.token`、`res.data.id`、`res.data.roleType` 读取，而 `api/auth.ts` 的类型声明又是 `data.user.id`。三处三套结构。后果：`setToken(undefined)` → localStorage 存成字符串 `"undefined"`；`setProfileCache` 写入 `regionId: ''`、`realNameVerified: undefined`，导致实名认证拦截与区县过滤链路不可靠；`utils/request.ts` 只在 401 时清 token，不会识别 `"undefined"`。 |

### P0-4 操作日志写入是 fire-and-forget，审计日志会静默丢失

| 项 | 内容 |
| --- | --- |
| **问题** | `LogService.log()` 是 `async` 方法，内部 `try/catch` 只 `console.error`；**所有调用方均未 await**，Promise 悬空。文档把"日志只追加、至少保留 5 年、支持全链路审计"当作核心设计原则（`docs/分光器资源管理系统_数据库设计.md:11,197`），实际写入不可靠。此外 `ip` / `userAgent` 除小程序登录外从未采集。 |
| **解决办法** | ① `log()` 返回 `Promise<void>`，所有调用点改为 `await this.logService.log({...})`（约 20 处）；<br>② 更彻底方案：用 NestJS 拦截器统一采集 `ip`/`userAgent` 并通过 `AsyncLocalStorage` 或请求上下文传递；<br>③ 失败时至少升级为 `Logger.error` 而非 `console.error`，避免审计静默丢失。 |
| **文件名** | `server/src/modules/log/log.service.ts` 及全部调用方 |
| **行数** | 定义：`server/src/modules/log/log.service.ts:79-103`（尤其 `:88-102` 的 try/catch）<br>典型未 await 调用点：`server/src/modules/auth/auth.service.ts:50`、`server/src/modules/community/community.service.ts:155,252,293,334,392`、`server/src/modules/splitter/splitter.service.ts:359,498,559,600,654,753`、`server/src/modules/user/user.service.ts:91,186,215,246,281`、`server/src/modules/permission/permission.service.ts:118,162`、`server/src/modules/region/region.service.ts:137,162,207` |

## 二、P1 级问题（安全与权限）

### P1-1 禁用/删除账号后，已签发 token 仍可用满 7 天

| 项 | 内容 |
| --- | --- |
| **问题** | `JwtStrategy.validate()` 只回填 payload，**不查库**校验 `status` / `is_deleted`；`JwtModule` 默认有效期 7d。文档多处承诺"账号禁用后已签发 token 在下次请求时拦截失效"（`docs/分光器资源管理系统_权限模块需求.md:16,47`），实际完全未实现；系统也没有登出接口与 token 黑名单。 |
| **解决办法** | ① 最小改动：把 `JwtStrategy` 改为注入 `PrismaService`，`validate()` 改为 `async`，查 `sysUser` 校验 `status===1 && isDeleted===0`，否则抛 `UnauthorizedException({ code: 1002 })`；<br>② 目标方案：`jti` + Redis 黑名单，禁用/登出时写黑名单并设 TTL=token 剩余有效期；<br>③ 建议加 `GET /auth/logout` 接口。 |
| **文件名** | `server/src/modules/auth/strategies/jwt.strategy.ts` / `server/src/modules/auth/auth.module.ts` / `server/src/modules/user/user.service.ts` |
| **行数** | `jwt.strategy.ts:22-40`（`validate` 在 `:32-40`）；`auth.module.ts:16-25`（`expiresIn` 在 `:22`）；禁用入口 `user.service.ts:197-224` |

### P1-2 登录无限流、无失败锁定、无验证码；Redis 装了从没用

| 项 | 内容 |
| --- | --- |
| **问题** | 登录方法无任何失败计数与锁定逻辑；文档要求的"连续登录失败锁定账号 30 分钟""登录接口限流""登出 token 写入 Redis 黑名单"（`docs/分光器资源管理系统_业务错误码.md:17,35`；`权限模块需求.md:45,153`）一条未实现。`ioredis` 在依赖里、Redis 在 compose 里且配了密码，但全仓 `src` **0 处引用 Redis**。 |

| **行数** | 登录逻辑：`auth.service.ts:23-48`（`:40-43` 密码校验失败即返回，无计数）<br>依赖声明：`server/package.json:38`（`ioredis`）<br>Redis 服务：`docker-compose.prod.yml:26-41`<br>环境变量：`server/.env.example:8-12` |

### P1-3 小程序登录是伪实现，且会撞唯一约束

| 项 | 内容 |
| --- | --- |
| **问题** | `miniLogin` 直接 `const openid = 'mini_' + code;`（注释自认"简化实现，实际项目需调用微信接口"），完全未调用 `jscode2session`；同时用 `account: \`mini_${code.substring(0,10)}\`` 而 `account` 是 `@unique`，不同 code 前 10 位相同即触发唯一冲突（500）；`code` 本质是一次性登录凭证，不能当稳定 openid 使用。等价于**任意人构造 code 即可登录成他人**。 |

| **文件名** | `server/src/modules/auth/auth.service.ts` / `server/src/modules/auth/dto/mini-login.dto.ts` / `server/.env.example` |
| **行数** | `auth.service.ts:157-179`（伪造 openid 在 `:160`，account 派生在 `:170`）<br>DTO：`server/src/modules/auth/dto/mini-login.dto.ts:1-6`<br>env 占位：`server/.env.example:21-23` |

### P1-5 行政区划接口对任何登录用户开放

| 项 | 内容 |
